# 2026년 10월 21일 보안관제 자동화 프로젝트 작업일지

> **프로젝트:** Graylog 6.1 · n8n · Discord 기반 보안 이벤트 탐지 및 알림 자동화  
> **작업일:** 2026-10-21  
> **검증 범위:** 모의 GELF 보안 로그 수신 → Graylog Event Definition 탐지 → HTTP Notification → n8n 판정 → Discord 알림  
> **주의:** 실제 방화벽 IP 차단, 계정 잠금, RBAC 권한 회수 및 Flask 대시보드 API 실행 검증과는 구분함.

## 1. 오늘의 핵심 결과

- Graylog Docker 이미지가 `graylog/graylog:6.1`임을 확인하고, 수업에서 사용한 Content Pack Export를 기준으로 n8n 연동용 **Event Definition 7개 + HTTP Notification 7개**를 구성했다.
- 초기 Content Pack 설치 시 `Missing Stream for event definition` 오류를 Graylog 컨테이너 로그에서 확인했고, 환경에 존재하지 않는 Stream 참조를 제거한 수정본 설치에 성공했다.
- Graylog의 모의 GELF 로그 수집 및 검색, Event 생성, n8n Webhook 호출, Discord 알림의 연결을 단계별로 점검했다.
- **ED-01·04·05·06·07·08·09 총 7개 규칙**에 대해 모의 로그 기반 탐지와 n8n 연동 테스트 완료를 확인했다.
- 포트폴리오 Markdown에 탐지·판정·알림 증빙을 누적하고 PDF 인쇄본과 성과 중심 소개본으로 정리했다.
- 실제 Wazuh Manager·Agent 연동 경로를 검토했으나, **오늘 확인된 Wazuh 경보는 모의 GELF 로그를 사용한 테스트**다.

## 2. 구성 환경과 데이터 흐름

| 구성 요소 | 역할 | 확인 내용 |
|---|---|---|
| Graylog 6.1 | 보안 로그 검색·집계·경보 생성 | Content Pack 설치 및 Event 생성 확인 |
| MongoDB / OpenSearch | Graylog의 메타데이터·검색 저장소 | Docker 기반 Graylog 구성에 포함 |
| GELF UDP Input | 모의 로그 수신 | Windows PowerShell에서 `127.0.0.1:12201/UDP`로 로그 전송 |
| Graylog Custom HTTP Notification | 탐지 이벤트를 n8n으로 전달 | Docker 환경에서 `host.docker.internal:5678` 활용 |
| n8n | 경보별 필드 변환·판정 및 메시지 생성 | Webhook별 실행 이력 확인 |
| Discord Webhook | 보안 경보 표시 | 탐지 유형별 Embed 메시지 수신 확인 |
| Flask 관련 HTTP 노드 | 실제 차단·기록 API 호출 | 테스트 당시 서버가 없어 의도적으로 비활성화 |

```text
[PowerShell 모의 GELF 로그]
          ↓
[Graylog GELF Input / Search]
          ↓
[Event Definition / Aggregation]
          ↓
[Custom HTTP Notification]
          ↓
[n8n Webhook → 판정함수 → 메시지]
          ↓
[Discord 보안 알림]
```

## 4. 오늘 해결한 주요 기술 문제

### 4.1 Content Pack 설치 중 HTTP 500 오류

- 증상: Graylog 설치 시 `Failed to install content pack` / Internal Server Error.
- 확인: `docker logs --since 30m gl-graylog`에서 `Caused by: ... Missing Stream for event definition` 발견.
- 대응: Content Pack의 Event Definition에 남아 있는 실습 환경의 Stream 참조를 제거한 수정본을 설치.
- 결과: 7개 Event Definition 및 Notification 구성 적용 성공.

### 4.2 Graylog Notification에서 빈 IP·집계 횟수 전달

- 초기 테스트 알림은 `src_ip: ""`, `count: ""`로 들어와 n8n 판정함수가 입력을 제외했다.
- 실제 Graylog Event 상세에서는 IP 그룹 키와 `count()=12.0` 등의 집계 결과가 생성됨을 확인했다.
- 알림 단독 테스트의 샘플 이벤트와 **실제 탐지 이벤트의 Notification 출력은 구분**해야 함을 확인했다.
- 이후 실제 이벤트 기반 Webhook 수신에서 `src_ip=203.0.113.30` 전달을 확인했다.
- 다만 일부 Discord 경보에 실패 횟수 `0회`가 표시된 이력이 있으므로, 실집계값을 직접 전달하는 부분은 계속 정확성 검증이 필요하다.

### 4.3 Graylog Notification URL 승인 문제

- ED-09는 Graylog 내부에서 탐지했지만 n8n에 전달되지 않았다.
- 원인: Notification의 대상 URL 승인 설정.
- 대응 후 n8n 경보 연동이 정상 동작함을 확인했다.

### 4.4 탐지 범위와 대응 조치의 구분

- ED-04: **출발지 IP** 기준 탐지 및 차단 대상 판정.
- ED-08: **대상 계정** 기준 탐지 및 잠금 대상 판정. 출발지 IP는 필수 판정 키가 아님.
- ED-06: 기존 단순 로그인 실패 집계가 ED-04·08과 동시 발동하던 구성에서 `incident-post-action` 기반 **모의 후속 공격** 시험으로 역할을 분리.
- Flask API 연동 노드는 테스트 중 비활성화했고 실제 조치 성공을 주장하지 않음.

## 5. 실제 증빙으로 확인한 대표 장면

- **ED-01:** Graylog RBAC 이벤트 생성, n8n 실행 `#370` 성공, Discord `[HIGH] 보안 접근 거부 판정`.
- **ED-05:** 검색된 모의 공격 로그 12건, Graylog `card(rule)=2.0`, n8n 실행 `#371` 성공, Discord 복합 보안 위협 탐지.
- **ED-06:** `incident-post-action` 후속 공격 로그, ED-06 인시던트 생성, n8n 실행 `#373` 성공, Discord `[HIGH] 보안 인시던트 리포트`.
- **ED-07:** Wazuh 4종 Discord 경보 캡처, Graylog 이벤트 및 n8n 실행 화면 확보.
- **ED-04·08·09:** Graylog 탐지 및 n8n 연결 화면을 확보했고, ED-04·08은 Discord 경보 화면도 확인했다.

※ 이 작업일지는 텍스트 단독 기록이다. 이미지 자료는 별도로 제작한 포트폴리오의 스크린샷 포함 ZIP 및 PDF를 참조한다.

## 6. 문서·포트폴리오 작업

- Graylog–n8n 연동 설정 가이드 및 Graylog 6.1용 Content Pack을 제작·설치 시험했다.
- 각 규칙 완료 결과에 따라 Markdown 진행 기록을 누적 갱신했다.
- 증빙 스크린샷을 모아 포트폴리오 v1.9로 정리했다.
- A4 인쇄 최적화 PDF 및 성과 중심 PDF로도 재편집했다.
- 외부에 보여줄 문서에서는 **검증된 탐지·판정·알림 성과**를 중심으로 설명하고, 실제 자동 차단·권한 회수까지 완료한 것처럼 표현하지 않도록 범위를 구분했다.

## 7. 다음 작업: 실제 Wazuh 연동

1. `docker ps -a`로 Wazuh Manager 실행 여부 및 컨테이너 이름 확인.
2. Manager의 `/var/ossec/logs/alerts/alerts.json` 존재 여부와 실경보 생성 확인.
3. 실제 경보 JSON을 Graylog로 전달할 수집기(예: Fluent Bit, Vector 또는 전달 스크립트) 구성.
4. `rule.id`, `rule.level`, `agent.name`, `data.srcip`, `syscheck.path`를 기존 Graylog의 `wazuh_*` 필드에 매핑.
5. 실제 Wazuh Agent에서 안전한 파일 생성·변경·삭제 테스트 후 **Wazuh → Graylog → n8n → Discord** 전체 경로 검증.
6. 검증 완료 시 모의 경보 실습 기록과 구분하여 포트폴리오에 새 증빙 추가.

## 8. 오늘의 결과 요약 (포트폴리오용)

2026년 10월 21일, Graylog 6.1과 n8n·Discord를 연동해 7종의 보안 이벤트 탐지 및 자동 알림 시나리오를 검증했다. 수업용 Content Pack Export를 활용해 규칙 및 HTTP Notification을 구성하고, 설치 오류와 필드 매핑·URL 승인 문제를 해결했다. IP·계정 단위 브루트포스, 복합공격 상관분석, 관리자 권한 오용, Wazuh 형식의 파일 무결성 경보, 웹스캐너 404 폭주, 모의 후속 공격 인시던트까지 서로 다른 로그 패턴의 경보 생성과 n8n 분기·Discord 전달을 확인했다. 다음 단계는 실제 Wazuh Manager·Agent의 경보를 Graylog 수집 경로에 연결하는 것이다.
