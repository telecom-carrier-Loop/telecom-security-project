# Zabbix PC 상태 대시보드 변경

- 로컬 코드 변경: PC1/PC2 연결 상태 추가. D 드라이브·이더넷 RX/TX 표시와 history 조회 제거. CPU/RAM/C 드라이브, 기존 서비스·장애 목록은 유지.
- 기본 감시 대상은 물리 PC1 192.168.3.18, PC2 192.168.3.19. 다른 대상을 원하면 backend 환경변수 ZABBIX_PC1_IP, ZABBIX_PC2_IP를 설정하고 해당 주소의 Zabbix 감시 항목을 생성해야 합니다.
- 기존 telecom-services 호스트에 simple check 4개 추가. item ID 50965~50968. 기존 항목·트리거·알림 정책은 삭제하거나 수정하지 않았습니다.
- ICMP 또는 에이전트 TCP 10050 또는 해당 PC의 기존 서비스 포트 중 최근 180초 내 하나라도 성공하면 ON. 모든 대상 검사가 최근 데이터로 실패하면 OFF. 데이터 없음·오래됨·지원 안 됨·항목 비활성화이면 확인 불가. 네트워크 응답 기준이며 실제 전원 센서가 아닙니다.
- PC1은 Ping/10050이 차단되어도 기존 Graylog 포트가 응답하면 ON으로 판정합니다. OFF는 방화벽 또는 네트워크 장애도 포함할 수 있습니다.
- 서버 상태 및 지표는 기존처럼 웹에서 30초마다 새로 조회합니다.
- 실제 Zabbix API 조회 결과 PC1/PC2 ON, resource metrics/history에 cpu/ram/disk_c만 남은 것을 확인했습니다.
- 검증: 전용 backend 테스트 5개 통과, 프론트 typecheck 및 production build 통과, git diff --check 통과, UI 정적 detector 지적 없음. 브라우저 시각 검증은 수행하지 않았습니다.
- Kubernetes 웹 배포, 커밋, 푸시는 수행하지 않았습니다. 웹에 반영하려면 이 frontend/backend 코드가 포함된 버전을 빌드·배포해야 합니다. 이미 추가한 Zabbix 항목만으로 기존 배포 웹에 새 카드가 생성되지는 않습니다.

## 감시 항목 생성 도구

```powershell
python infrastructure/tools/setup_zabbix_nodes.py
python infrastructure/tools/setup_zabbix_nodes.py --apply
```

첫 명령은 미리보기이며 두 번째 명령만 누락 항목을 추가합니다. 기존 항목을 변경하지 않고 동일 key가 있으면 건너뜁니다. 기존 backend의 ZABBIX_API_URL/TOKEN 환경 설정을 읽고 토큰은 출력하지 않습니다. 재배포 시 이 도구를 웹 요청 안에서 자동 실행하지 마세요.
