# 2026-10-29 결제 안내·멤버십·차단 목록 변경

> 후속 요청으로 Admin은 고객 멤버십에서 제외하고 관리자 역할로 정리했다. 아래 초기 4등급 설명은 당시 작업 기록이며, 현재 동작은 [후속 멤버십 개편](2026-10-29-멤버십-레이아웃-업그레이드안내.md)과 [현재 API 계약](../contracts/membership-api.md)을 따른다.

## 사용 방법

1. 고객의 요금 납부 화면에서 카카오페이를 누르면 `결제 시스템은 준비중 입니다.` 안내창을 표시한다. 결제 준비 API 호출과 외부 결제 페이지 이동은 하지 않는다. 테스트 카드 납부는 유지한다.
2. 관리자 → 회원 → 대상 회원의 `등급 조정` 또는 이름 → `멤버십 등급 조정`에서 등급과 변경 사유를 입력한다. 확인창 승인 후 저장한다.
3. 보안 관리의 `차단 IP`와 `차단 계정`을 각각 선택해 조회한다. 두 화면 상단에도 전환 메뉴를 제공한다.

## 멤버십 처리

- 표시 등급은 일반유저 / Plus / VIP / Admin이다.
- Admin 멤버십은 실제 ADMIN 관리자 권한을 부여하지 않는다. 실제 관리자 계정의 승격·강등 API를 추가한 것이 아니다.
- 기존 DB의 rank 0/1/2/3을 새 표시 이름에 대응한다. 기존 내부 코드 BASIC/SILVER/GOLD/VIP와 외래키·잔액·적립률은 보존한다. 별도 스키마 마이그레이션은 필요 없다.
- 따라서 기존 rank 2(Gold)는 VIP, rank 3(VIP)는 Admin 멤버십으로 표시된다. 사용자 role은 그대로다.
- 신규 자동 가입의 등급 산정에서는 Admin을 제외한다. Admin은 관리자가 지정한다.
- 미가입 고객의 등급을 관리자가 지정하면 포인트 0으로 가입한다. 기존 포인트 잔액은 바꾸지 않고 변경 내역은 감사 로그에 저장한다.
- 기존 상품·혜택의 최소 rank 정책은 유지한다. 기존 최고 rank 상품·혜택은 새 이름 기준 Admin 등급 대상이다. 상품의 자유 입력 이름·설명은 자동 수정하지 않는다.

## 차단 계정 조회

- 새 화면: `/admin/account-locks`
- 새 API: `GET /api/admin/account-locks?page=1&q=...`
- 실제 ADMIN 세션만 조회한다. 활성 상태이면서 `locked_at`이 있는 계정을 고객·관리자 구분 없이 표시한다.
- 이름, 마스킹된 이메일, 실제 사용자 권한, 잠금 시각·사유, 검색·페이지 이동·새로고침을 제공한다. 탈퇴 계정은 제외한다.
- 고객 잠금 관리 동작은 기존 회원 관리 화면을 이용한다. 새 화면에서 관리자 계정을 임의로 해제하는 기능은 추가하지 않았다.
- IP 차단·계정 잠금·해제의 기존 자동조치 API는 수정하지 않았다.
- 실행 중인 이전 Flask가 새 조회 API에 404를 반환할 경우에만 기존 관리자 전용 `/api/admin/customers?status=LOCKED`로 호환 조회한다. 이 모드에서는 고객 계정만 표시된다는 안내를 제공한다. 401·403·503 오류를 빈 목록으로 바꾸거나 우회하지 않는다.
- 왼쪽 메뉴는 스크롤바를 숨기고 행 간격을 줄였다. 화면이 낮을 때도 휠·키보드로 나머지 메뉴에 접근할 수 있도록 스크롤 기능은 유지한다. 터치 기기의 메뉴 항목은 최소 높이 44px를 유지한다.

## 검증 및 실행

- 전체 백엔드 테스트 127건 통과(신규 14건 포함). 프런트엔드 타입 검사·빌드 및 코드 검토 통과.
- 신규 테스트는 관리자 전용 접근, CSRF, 입력 검증, 등급 변경·감사 로그, 잔액 보존, 실제 관리자 권한과의 분리, 미가입·탈퇴 처리, Admin 자동 가입 방지, 차단 계정 조회·검색·마스킹을 확인한다.
- SQLite 메모리 DB에서 테스트한다. 실제 DB에 마이그레이션·시드·등급 변경을 실행하지 않았다.
- 기존 관제 테스트는 로컬 `.env`의 Grafana URL이 기대 기본값에 영향을 줬으므로 테스트 프로세스 안에서 관제 URL 환경변수를 분리해 검증한다. `.env` 파일은 변경하지 않는다.
- 브라우저의 저장된 접근 정책으로 직접 UI 검증은 진행하지 않았다. 타입 검사·빌드·API 테스트 및 코드 검토 범위와 구분한다.
- 프런트엔드만 갱신하면 새 관리자 API가 생기지 않는다. 로컬 Flask를 중단 후 기존 DB 설정을 유지해 다시 실행하거나, 배포 환경에서는 수정된 백엔드도 함께 반영해야 한다.
- 기존 2026-10-28 작업 정리 문서는 보존한다. 이번 변경은 별도 커밋·푸시·실서버 배포를 하지 않는다.
