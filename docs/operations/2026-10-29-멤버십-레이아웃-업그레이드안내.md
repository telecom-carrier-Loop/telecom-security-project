# 2026-10-29 멤버십 레이아웃 및 업그레이드 안내

## 화면 변경

- 관리자 상단에 사용자 페이지로 이동하는 버튼을 항상 표시한다. 로그인 역할을 바꾸거나 고객 계정으로 가장하는 동작은 아니다.
- 회원 목록의 멤버십 열은 `등급 변경` 버튼과 오른쪽 현재 등급으로 구성한다. 버튼은 해당 회원 상세의 등급 편집 영역으로 이동하며, 데이터 로딩 후 해당 위치로 스크롤한다.
- 멤버십은 본문과 오른쪽 적립률 안내의 2열로 구성한다. 우측 안내는 이 페이지 안에서만 `position: sticky`로 따라오고, 모바일에서는 일반 문서 흐름으로 바뀐다.
- 포인트 패널의 과도한 높이를 없애고 본문 폭에 맞는 업그레이드·혜택 카드와 제한된 내부 스크롤을 가진 포인트 표를 배치한다.
- 미가입 상태, 조회 중, 오류, 빈 내역을 구분한다.

## 고객 등급과 Admin 역할

- 고객 멤버십: 일반유저 / Plus / VIP.
- Admin은 관리자 역할이며 고객 등급 표·구매 카드·선택 옵션에서 제외한다. 실제 역할·세션 권한 변경 기능은 추가하지 않는다.
- 새 API에서도 고객 등급은 세 가지만 반환하며, 관리자 등급 조정에서 rank 3 지정은 거부한다.
- 과거 rank 3 계정은 행이나 잔액을 직접 수정하지 않고 고객 화면·향후 적립·혜택·상점 정책에서 VIP로 호환한다. 과거 최고 rank 상품·혜택 조건도 VIP 기준으로 해석한다.
- 홈·멤버십·상점에서는 이전 백엔드의 등급 이름도 고객용 이름으로 정규화한다.

## 업그레이드 동작

- 사용 가능한 포인트 아래에 일반유저·Plus·VIP 카드를 표시한다.
- 현재·하위 등급은 업그레이드 대상으로 활성화하지 않는다.
- 상위 등급의 `업그레이드하기`를 누르면 정확히 `결제 시스템은 준비중입니다.`를 표시한다.
- 결제 서비스와 구매 가격이 아직 정해지지 않아 임의 금액을 표시하지 않는다. 이 버튼으로 결제·포인트 차감·등급 변경 API를 호출하지 않는다.
- 실제 결제 성공 후 등급을 바꾸는 처리는 결제 서비스 구현 시 서버 검증과 함께 연결해야 한다. 현재 결제된 것으로 간주해 등급을 바꾸지 않는다.

## 검증 및 적용

- 전체 백엔드 테스트 130건 통과. 세 등급 조회, rank 3 변경 거부, 과거 rank 3의 VIP 호환·적립률, 기존 포인트 보존과 관리자 권한 분리를 포함한다.
- 프런트엔드 타입 검사·빌드, 변경 형식 검사 및 코드 검토 통과.
- 브라우저 접근 정책 때문에 데스크톱·모바일 실제 렌더링 검증은 수행하지 않았다. 스크린샷 기반 요구사항과 CSS·컴포넌트 검토 결과를 구분한다.
- 로컬 Flask는 새 API·정책을 반영하려면 기존 실행 창에서 중단 후 DB 환경변수를 유지해 다시 실행해야 한다. DB 초기화·시드·마이그레이션은 필요 없다.
- 실서버 배포·커밋·푸시는 수행하지 않았다. 기존 미커밋 작업과 작업 정리 문서는 보존했다.
