# 보안관제 통합 프로젝트 — 누구나 이해하는 진행 현황 및 운영·테스트 안내

> 기준일: **2026-10-23** | 환경: Windows PC1·PC2, Docker, Ubuntu VM | 기록 범위: 대화에서 실제 확인된 결과 중심

## 1. 한눈에 보기

이 프로젝트는 **컴퓨터나 서버에 보안상 중요한 일이 생기면, 자동으로 찾아서 Discord에 알려 주는 시스템**입니다. 사람이 여러 컴퓨터의 로그를 계속 열어 보지 않아도, Wazuh가 컴퓨터 상태를 감시하고 Graylog가 경보를 모으며 n8n이 알림을 만들어 Discord로 전달합니다.

**최종 확인:** PC1 Windows 테스트 경보가 Graylog에 도착해 Event Definition이 이벤트를 만들었고, **n8n을 거쳐 Discord 메시지까지 실제 도착**했습니다. PC2 Ubuntu VM의 파일 변경·삭제(FIM) 경보도 별도로 **Wazuh → Graylog → n8n → Discord** 연동 성공했습니다.

### 전체 구조 (비전공자용)

```text
[PC1 Windows 컴퓨터] -- Wazuh Agent --┐
                                    ├→ [각 PC의 Wazuh Manager]
[PC2 Ubuntu 가상머신] -- Wazuh Agent ┘           │
               PC1 Manager / PC2 Manager 각각 운영  │ JSON Syslog UDP 5140
                                                 ▼
                                      [PC1 Graylog — 보안 로그 통합]
                                                 │
                               이벤트 탐지 / HTTP Notification
                                                 ▼
                                       [PC2 n8n — 자동화]
                                                 │
                                        메시지 구성 및 전달
                                                 ▼
                                          [Discord 채널]
```

**정확한 연결:** PC1 Windows Agent → **PC1** Wazuh Manager → PC1 Graylog; PC2 Ubuntu Agent → **PC2** Wazuh Manager → **PC1** Graylog. Graylog에서 발생한 알림은 **PC2 n8n**으로 전송됩니다. PC2에는 별도로 **Wazuh Manager → PC2 n8n 직접 FIM 연동**도 있어, 동일 경보가 중복 알림으로 이어질 가능성이 있습니다.

## 2. 각 프로그램은 무슨 역할을 하나요?

| 구성품 | 쉬운 비유 | 실제 역할 |
|---|---|---|
| **Wazuh Agent** | 각 컴퓨터의 센서 | Windows 이벤트, Linux 파일 변경, 설정 상태 등을 감시하고 Wazuh Manager로 전달 |
| **Wazuh Manager** | 경비실 분석 담당자 | 받은 사건을 규칙으로 분석하고 Rule ID·심각도(Level)를 부여하여 경보 생성 |
| **Graylog (PC1)** | 종합 관제 상황판 | PC1·PC2 경보를 한 화면에 모으고 검색·분류·이벤트 생성 |
| **Graylog Stream** | 로그 분류함 | Wazuh 관련 메시지를 `Wazuh 경보` 스트림으로 묶음 |
| **Event Definition** | '이런 일이 일어나면 알림' 조건 | 특정 컴퓨터·규칙·심각도·파일 변경 조건을 만족할 때 이벤트 생성 |
| **HTTP Notification** | 상황 전달 담당자 | Graylog가 만든 이벤트를 n8n Webhook으로 HTTP 전송 |
| **n8n (PC2)** | 자동화 비서 | Webhook 수신 → 필요한 필드 추출/문구 작성 → Discord 전달 |
| **Discord** | 실시간 알림 게시판 | 담당자가 확인할 수 있는 보안 경보 메시지 표시 |
| **Docker** | 서비스별 독립 실행 공간 | Manager, Graylog, n8n 등 여러 프로그램을 컨테이너로 실행 |
| **OpenSearch / MongoDB** | Graylog의 보관·검색 기반 | Graylog의 검색 데이터 및 메타데이터를 뒷받침 |

**로그와 경보는 다릅니다:** Windows에 이벤트가 기록돼도 Wazuh 탐지 규칙에 매칭되지 않으면 `alerts.json`에 경보가 없을 수 있습니다. Graylog에서도 경보 로그가 들어온 것과 Event Definition의 이벤트가 만들어지는 것은 서로 다른 단계입니다.

### 실제로 어떤 경보를 만들었나?

**Windows:** 관리자 PowerShell에서 `eventcreate` 명령으로 Application 로그에 실습용 Warning(이벤트 777)을 작성 → Wazuh Manager 사용자 정의 규칙 `100290`이 Level 8로 경보 생성 → Graylog의 `ED-WZ-WINDOWS-PC1`이 이벤트 생성 → PC2 n8n → Discord. 이 테스트는 *실제 침입·공격이 아니라 탐지·전송 동작을 검증하기 위한 인공 이벤트*입니다.

**Ubuntu:** Ubuntu VM의 허용된 `/etc/ssh` 테스트 파일을 만들고 수정하고 삭제 → Wazuh FIM이 `554`(추가), `550`(수정), `553`(삭제)를 기록 → PC1 Graylog에서 `pc2-k3s` 경보 수신 → Event Definition 및 n8n 자동화 → Discord. `/var/log/journal`의 빈번한 변경은 알림 과다를 막기 위해 Event Definition에서 제외하거나 감시 대상을 제한하는 설계를 사용했습니다.

## 5. 문제 해결 기록 (왜 설정을 바꿨나요?)

1. **Graylog에 메시지가 없어 보임:** Search의 시간 범위가 좁았음. `All Time`으로 바꾸니 `board-host` 로그 발견. 검색할 때 시간 범위를 먼저 확인.
2. **Windows 이벤트는 생성됐지만 보안 경보가 없음:** 이벤트 ID `777`은 자동으로 Level 7 이상이 되지 않음. 실습 전용 Rule `100290` 생성 후 규칙 관계를 조정하고 실제 이벤트를 최종 확인.
3. **Windows 기본 규칙과의 연결:** Wazuh의 `60000`은 Windows EventChannel 계열, `60003`은 Application 계열 분류 규칙. 시도 중 `<if_sid>60003</if_sid>` 및 `<if_group>windows_application</if_group>` 접근을 검토. 실제 성공 시점의 최종 적용 규칙 파일을 별도로 보관·확인 권장(이 문서는 최종 파일 전문을 확인한 증거가 없음).
4. **Wazuh Manager 내부 서비스가 한 차례 전부 멈춤:** Docker 컨테이너가 실행 중이어도 `wazuh-db`·`analysisd`·`remoted` 등이 중지될 수 있었음. `wazuh-control start`로 내부 서비스를 시작해 복구했고, 이후 `restart`에서도 모든 필수 서비스가 정상 시작됨. OOM 여부는 확정하지 못함.
5. **PC1과 PC2의 서로 다른 Manager:** Wazuh Agent가 각각 자기 Manager로 보내며, 최종 경보 수집 위치만 PC1 Graylog로 통일. Linux FIM의 직접 PC2 n8n 경로는 별도 존재하므로 중복 알림 주의.
6. **PowerShell/Docker 인용부호 문제:** `docker exec ... grep -F '문자열' /경로`처럼 `sh -c` 없이 전달하거나 PowerShell `Select-String` 활용.

## 6. 지금 상태와 아직 남은 작업

### 완료
- PC1 Windows Agent → Wazuh Manager → PC1 Graylog → PC2 n8n → Discord **실제 종단간 성공**.
- PC2 Ubuntu FIM → PC2 Wazuh Manager → PC1 Graylog → PC2 n8n → Discord **실제 종단간 성공**.
- Wazuh 경보와 Graylog 이벤트 각각 확인, 시스템 장애 후 PC1 Manager 복구.

### 남은 작업 / 운영 주의
- **PC1 `loop-web` Ubuntu VM**에 Wazuh Agent가 설치·연결됐는지 최종 확인 (완료로 표시하면 안 됨).
- PC2 Ubuntu 24.04용 SCA 실습 정책은 간단한 **4개 자체 검사 통과**로, 공식 CIS 전체 평가 100%를 의미하지 않음.
- PC2 FIM 직접 연동 + Graylog 경유 연동이 동시에 켜져 있으면 Discord 중복 알림 가능. 운영 전에 중복·알림 빈도 점검.
- PC1의 `100290`은 운영용 공격 탐지 규칙이 아닌 **실습용 규칙**. 통합 시험이 끝나면 제거 또는 비활성화 여부를 결정하고, 실제 필요한 보안 규칙으로 교체.
- 로그와 이벤트가 실제로 발생할 때만 n8n/Discord로 보냄. **수신 검증은 성공했지만 자동 IP 차단, 계정 잠금, Flask API까지 실제로 작동했다는 뜻은 아님.**
- Wazuh Manager 재기동 장애가 재발하면 서비스 상태·컨테이너 로그·리소스를 살핀 후 복구. Agent 등록 DB 파일 임의 삭제 금지.
- Discord Webhook URL, API 키, 비밀번호, 개인 계정·PC 보안정보는 공유 자료에 포함하지 말 것.
