# 2026년 10월 30일 작업 내역

## 1. Wazuh 병렬 전송 및 기존 자동화 유지

- Wazuh 경보를 Graylog의 로그 저장·검색 경로와 n8n의 웹 기록·자동조치·Discord 경로로 각각 전달하도록 구성했습니다.
- 기존 n8n의 웹 기록·IP 차단·알림 흐름과 인증 설정을 유지하면서 Wazuh 직접 수신 경로를 연결했습니다.
- 직접 전송 서비스의 실행 상태와 인증 불일치, 집계 숫자가 문자열로 들어오는 처리 문제를 점검·수정했습니다.
- 정상 로그 변경 및 Windows 정상 로그인에서 발생하는 반복 Discord 알림을 호스트·규칙·경로 단위로 제한했습니다. 해당 이벤트의 수집과 웹 기록은 유지했습니다.
- Graylog Notification 연결 해제는 사용자가 별도로 진행하며, 최종 검증에서는 확인 대상에서 제외했습니다.

## 2. Graylog 21개 탐지 항목의 Wazuh 구현

- 로그인 실패, 동일 IP/계정 집계, 복합 공격, 잠금 이후 시도, 404, 요청량, 포트 다양도·SYN·패킷량, 심야 로그인, SQLi·Nikto 의심, 내부 비인가 접근, 로그 변조 및 호스트/FIM 항목에 대응하는 규칙과 집계를 구성했습니다.
- 기존 규칙 번호 충돌을 피하기 위해 Linux 호스트 규칙을 110730~110738, API 컨테이너 파일 감시를 110750~110752로 분리했습니다.
- Wazuh의 로그인 계정 필드 dstuser를 집계기가 읽도록 보완했습니다.
- Low and Slow 자동 분류에 실제 시간 분산 조건을 적용하고 KST 심야 시간 판정을 확인했습니다.
- 계정 자동 잠금·권한 회수는 기존 OFF 정책을 유지했습니다. 탐지 구현 완료가 모든 자동조치 활성화를 뜻하지는 않습니다.

## 7. Zabbix 관리자 대시보드 변경

- 사용자 최종 지정에 따라 물리 PC가 아닌 Kubernetes VM PC1 192.168.7.185, PC2 192.168.7.100을 감시 대상으로 확정했습니다.
- 관리자 화면에 VM별 ON/OFF/확인 불가 및 마지막 측정 시각을 추가했습니다.
- ON/OFF는 ICMP·SSH 및 등록 서비스의 네트워크 응답 기준입니다. 실제 전원 센서가 아니므로 OFF에는 네트워크·방화벽 장애도 포함될 수 있습니다.
- 오래된 측정값, 지원 안 됨, 미수집·비활성화는 확인 불가로 처리합니다.
- 이더넷 RX/TX 및 D 드라이브 표시와 history 조회를 제거했습니다. CPU/RAM/C 드라이브와 기존 서비스·활성 장애 목록은 유지합니다.
- Zabbix telecom-services 호스트에 VM용 item 50969~50972를 생성했습니다. 임시로 추가했던 물리 PC용 50965~50968만 식별 후 삭제했고 기존 감시 항목은 유지했습니다.
- 실제 API 조회에서 두 VM ON 및 metrics/history가 cpu/ram/disk_c만 포함하는 것을 확인했습니다.
- 관련 테스트 5개, 프론트 production build, diff 공백 검사를 통과했습니다. 브라우저 시각 검증은 수행하지 않았습니다.
- 이 Zabbix 대시보드 코드의 운영 웹 재배포·커밋·푸시는 진행하지 않았습니다. 앞선 Wazuh 관측 모듈 배포와 구분됩니다.
