# 백업 운영 — B

공용 PC의 Linux 작업은 매일 02:00 KST에 `backup.sh`를 실행합니다. 서버 timezone과 cron/systemd timer의 timezone을 함께 기록합니다. 최근 일별 7개와 주별 4개를 서로 구분해 보관하고 두 PC와 분리된 매체에 사본을 둡니다.

- 백업 계정·클라이언트 설정은 보호 경로에 두고 권한 600, 앱 계정과 분리합니다.
- GPG 공개키의 전체 fingerprint를 직접 확인합니다. 개인키와 복호화 정보는 별도 보관합니다.
- DDL/Migration과 동시에 논리 백업을 하지 않습니다. InnoDB 기준입니다.
- `--set-gtid-purged=OFF` 앱 논리 백업은 Replica 초기화용 일관된 GTID 스냅샷을 대신하지 않습니다.
- 암호화·체크섬·외부 복사를 확인하고 매주 및 시연 전 별도 DB에서 복원합니다.
- 삭제 자동화는 아직 제공하지 않습니다. 검증된 주별 사본과 보존 정책 확인 뒤 만료 파일만 정리합니다.
- 스크립트의 성공 로그는 백업 생성 성공이며 복원 검증 성공과 별도입니다. D가 실패 exit code도 수집해야 합니다.
- Windows 실습의 `mysql-lab.py restore-test`는 합성 데이터·별도 컨테이너의 논리 복원을 확인합니다. GPG 암호화·공용 PC 매체·예약 실행은 별도 실증해야 합니다.
